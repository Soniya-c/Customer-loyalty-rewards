# BoxPoints — Customer Loyalty Rewards

A small web app for a factory that sells physical products in boxes. Customers enter a unique code printed inside a box and earn points. Factory staff sign in to generate batches of codes and monitor customer balances, redemptions, and unused inventory.

## What the app does
- **Purchase proof:** each box contains a unique, unpredictable code generated by the factory. A customer submits that code and an email address.
- **Fraud/code reuse controls:** raw codes are never stored (SHA-256 digest only); codes are unique in the database; redemption is performed in a SQLite write transaction and only succeeds while status is `unused`; a redemption record has a unique code reference. Reusing a code is rejected.
- **Factory management:** password-protected dashboard shows customers, points issued, redeemed/unused code counts, customer balances, and recent activity. Admin can generate code batches (raw codes are shown once).
- **Rewards:** default 10 points per box; configurable with `POINTS_PER_BOX`.

## Tech stack
- Python 3.10+
- Flask 3.x (server-rendered pages and form handling)
- SQLite (local persistence, transactions and uniqueness constraints)
- HTML/CSS

## Setup and run
```bash
python -m venv .venv
# macOS/Linux:
source .venv/bin/activate
# Windows PowerShell:
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env
```
Edit `.env` and replace both placeholder secrets. Export the variables in your shell (or use your preferred dotenv loader). Example:
```bash
export APP_SECRET='a-long-random-value'
export ADMIN_PASSWORD='a-strong-password'
python app.py
```
Open http://127.0.0.1:5000. Factory login: http://127.0.0.1:5000/admin/login.

The app initializes the SQLite schema and seeds five demo codes on first start. Those demo raw codes are intentionally not printed to logs or shown in the UI; use the admin dashboard to generate a fresh batch for testing/packaging. For a clean local test, remove `rewards.db` and restart.

## Tests
Run `python -m unittest discover -s tests -v`. The suite covers successful redemption, duplicate redemption, unknown codes, and dashboard access. See [TESTS.md](TESTS.md) for manual checks and production test gaps.

## Deployment
No public deployment is configured for this repository. Deploy behind HTTPS using a production WSGI server (for example Gunicorn), persistent database storage, strong environment secrets, backups, and restricted admin access. Do not use Flask's development server in production.

## Important production hardening
This is a functional MVP, not a production-ready loyalty platform. Before a live launch add CSRF protection, per-IP and per-account rate limiting, secure cookie settings, admin password hashing/identity provider, audit logs, encrypted backups, database migration tooling, monitoring, and a controlled code-printing/export workflow. For multiple app instances, use PostgreSQL and atomic conditional updates. Protect printed codes in the packaging supply chain.
